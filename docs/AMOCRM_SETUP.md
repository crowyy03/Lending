# Подключение заявок с лендинга к AmoCRM

Заявки с формы уходят в AmoCRM через серверный API (Vercel Serverless). Создаётся **сделка** и привязанный **контакт** (телефон + email). Остальные поля формы (адрес, покрытие, высота дома, использование, заметки) попадают в примечание к сделке или в одно дополнительное поле.

---

## Шаг 1. Интеграция в AmoCRM и доступ к API

1. Зайди в AmoCRM под своим аккаунтом.
2. **Настройки** (шестерёнка) → **Интеграции** → **Создать интеграцию** (или используй существующую).
3. Укажи название (например «Лендинг AlexPRO Lights»), Redirect URI можно оставить пустым для серверного доступа.
4. Сохрани и получи:
   - **Client ID** (интеграция)
   - **Client Secret** (секретный ключ)
5. Для **постоянного доступа** нужен **Access Token**:
   - В карточке интеграции открой раздел «Авторизация» и пройди OAuth2: открой ссылку в браузере → войди в AmoCRM → разреши доступ → скопируй **access_token** из ответа (или сохрани **refresh_token** и при необходимости обновляй access_token по документации).
   - Либо используй готовый постоянный токен, если у тебя уже есть (например, из другого сервиса).
   - Без токена API не сработает — его нужно один раз получить и подставить в `AMOCRM_ACCESS_TOKEN` на Vercel.

Документация по OAuth: [AmoCRM — авторизация для интеграций](https://www.amocrm.ru/developers/content/oauth/step-by-step).

---

## Шаг 2. Узнать subdomain (поддомен)

В адресе AmoCRM у тебя что-то вроде: `https://**твой_поддомен**.amocrm.ru`.

- **Subdomain** — это `твой_поддомен` (без `.amocrm.ru`).
- Его нужно указать в переменной окружения `AMOCRM_SUBDOMAIN`.

---

## Шаг 3. Переменные окружения на Vercel

В настройках проекта на Vercel добавь переменные окружения:

| Переменная | Обязательно | Описание |
|------------|--------------|----------|
| `AMOCRM_SUBDOMAIN` | Да | Поддомен AmoCRM (например `mycompany`) |
| `AMOCRM_ACCESS_TOKEN` | Да | Токен доступа (Bearer) для API |
| `AMOCRM_PIPELINE_ID` | Нет | ID воронки, куда создавать сделки (по умолчанию — первая воронка) |
| `AMOCRM_STATUS_ID` | Нет | ID статуса в воронке (по умолчанию — первый статус) |
| `AMOCRM_FIELD_LEAD_NOTES` | Нет | ID поля типа «Текст»/«Примечание» у сделки — сюда пишутся адрес, покрытие, высота, использование, заметки |

Без `AMOCRM_SUBDOMAIN` и `AMOCRM_ACCESS_TOKEN` заявки в AmoCRM не отправляются.

---

## Шаг 4. (Опционально) Поле «Примечание» у сделки

Если хочешь, чтобы адрес, покрытие, высота дома, использование и заметки попадали в одно поле сделки:

1. В AmoCRM: настройки воронки → поля сделки → создай поле типа **Текст** (многострочное) или «Примечание».
2. Открой это поле и в URL или в API посмотри его **ID** (число).
3. Задай в Vercel переменную **`AMOCRM_FIELD_LEAD_NOTES`** = этот ID.

Тогда все доп. данные с формы будут записываться в это поле. Если переменную не задавать — сделка и контакт всё равно создаются, но текст примечания в сделку не пишется.

---

## Шаг 5. Pipeline и Status (опционально)

По умолчанию сделка создаётся в первой воронке и в первом статусе. Чтобы явно указать воронку и статус:

- **Pipeline ID** и **Status ID** можно посмотреть через API:  
  `GET https://{subdomain}.amocrm.ru/api/v4/leads/pipelines`  
  или в интерфейсе AmoCRM (в URL при открытии воронки/статуса иногда виден id).
- Задай их в переменных `AMOCRM_PIPELINE_ID` и `AMOCRM_STATUS_ID` на Vercel.

## Как потом поменять поля и данные

### Поля формы (адрес, телефон, способ связи, покрытие и т.д.)

- **На лендинге:** правь компонент формы в проекте:  
  `components/MultiStepForm.tsx` — состояние `formData`, инпуты и кнопки.
- Имена полей в объекте (например `address`, `phone`, `contactMethod`, `coverage`, `homeHeight`, `mainUse`, `notes`, `email`) должны совпадать с тем, что ожидает API.

### Что уходит в AmoCRM (маппинг полей формы → сделка/контакт)

- Логика формирования сделки и контакта: **`api/lead.ts`**.
- Сейчас:
  - **Сделка:** название, примечание (если задано `AMOCRM_FIELD_LEAD_NOTES`), воронка/статус (если заданы).
  - **Контакт:** телефон и email через стандартные коды полей `PHONE` и `EMAIL` (тип WORK).
- Чтобы изменить:
  - какие поля формы куда попадают — правь объекты `payload`, `_embedded.contacts`, `custom_fields_values` в `api/lead.ts`.
  - добавить новые поля сделки или контакта — добавь элементы в `custom_fields_values` с нужными `field_id` (или `field_code` для контакта) из AmoCRM.

### Добавить свои поля в AmoCRM (сделка или контакт)

1. В AmoCRM создай нужные поля у сделки или контакта, запомни их **ID** (или код, если есть).
2. В `api/lead.ts` в массив `custom_fields_values` добавь объект вида:
   - для сделки: `{ field_id: ID_ПОЛЯ, values: [{ value: 'значение' }] }`;
   - для контакта можно использовать `field_code` (например `PHONE`, `EMAIL`) или `field_id`.

После любых правок в `api/lead.ts` нужно заново задеплоить проект на Vercel.

---

## Локальная проверка

- Запросы с лендинга идут на **`/api/lead`** (тот же хост). На Vercel этот путь обрабатывается серверной функцией `api/lead.ts`.
- Локально при `npm run dev` маршрута `/api/lead` нет — форма вернёт ошибку. Чтобы проверить отправку в AmoCRM:
  - используй **`vercel dev`** (поднимает и фронт, и API локально), или
  - задеплой на Vercel и тестируй на превью/продакшене.
